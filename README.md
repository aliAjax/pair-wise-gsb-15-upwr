# FlowDesk Studio

FlowDesk Studio 是一个完全运行在浏览器中的企业级低代码流程编排与审批监控演示平台。项目使用 React、TypeScript、Vite、Zustand 和 React Flow，所有数据均为本地 mock，不需要后端、登录或外部 API。

## 启动

需要 Node.js 20+。

```bash
npm install
npm run dev
```

打开终端显示的本地地址（默认 `http://localhost:5173`）。建议使用 1440px 或更宽的现代桌面浏览器。

## 测试

首次运行先安装 Chromium：

```bash
npx playwright install chromium
npm test
```

Playwright 会自动启动 Vite（端口 4173），串行验证 Dashboard、编辑器审批配置、双区域校验、条件修复、动态表单预览、发布联动、异常实例详情、版本比较和历史恢复，并覆盖环境晋升链路：门禁拦截（缺映射、校验未过、基线变化）、冻结候选→映射占位审批人→晋升、正式/测试申请的版本来源。测试失败时会保留截图和 trace。

## 环境晋升（测试 → 正式）

测试环境与正式环境通过晋升流程隔离，避免占位审批人、试验字段直接进入真实申请：

1. **冻结候选**：编辑器中点击“冻结候选”，当前测试版被快照为候选版本（含结构指纹、正式基线版本与基线指纹）。此后测试申请始终使用该候选快照。
2. **晋升门禁**（`/workflows/:id/promote`）：三项检查全部通过才能晋升——
   - 候选快照校验无错误（含试验字段必须清理），并列出涉及节点；
   - 占位审批人（指定成员/固定角色的值不在企业人员、角色目录中）必须逐个映射为正式人员；
   - 基线一致性：草稿与正式版本自候选冻结后未再变化，否则列出新增/删除/变更的冲突节点。
3. **晋升**：映射写回候选快照后生成正式版本；正式申请只认带晋升记录的版本，测试申请继续走候选快照。
4. **版本历史**：晋升版本记录来源候选、冻结时间、晋升时间、快照指纹与完整审批人映射。


## 浏览器验证路径

1. Dashboard 点击“差旅费用审批”进入编辑器。
2. 选择“直属主管审批”，切换审批人来源并保存草稿。
3. 运行校验，观察 Condition 节点红色错误态和底部问题面板。
4. 选择“金额判断”，配置申请金额大于 5000，再次校验。
5. 打开预览，输入金额 12000，观察模拟分支切换。
6. 返回并发布；在 Dashboard 和 Workflows 检查状态及版本。
7. 进入运行监控，筛选异常并打开实例，查看时间线及高亮节点。
8. 从编辑器进入版本历史，选择两个版本比较，再恢复旧版本为草稿。
9. 编辑器点击“冻结候选”，进入晋升页观察门禁：缺映射、校验未过或基线变化时晋升按钮停住，并列出节点与冲突；补齐映射后晋升，在版本历史查看来源与映射，在预览页切换正式/测试申请确认版本来源。

## 项目结构

- `mock-data/`：12 个流程、80 个实例、8 个用户、6 个角色、5 个业务域及边界案例。
- `src/components/`：布局、公共状态组件和 React Flow 画布。
- `src/pages/`：Dashboard、流程列表、编辑器、表单预览、运行监控、版本历史、环境晋升。
- `src/lib/`：快照指纹、候选校验、占位审批人识别、基线差异与晋升门禁。
- `src/store/`：Zustand 全局状态、校验、发布、候选冻结、环境晋升、复制、归档及恢复逻辑。
- `src/types/`：核心业务数据 TypeScript 类型。
- `tests/`：关键产品链路 Playwright 测试。

## Mock 边界案例

数据集中包含空流程、孤立审批节点、缺少结束节点、未配置条件分支、审批人为空、表单必填校验、超长流程名称、超长说明展示能力、无异常实例，以及由搜索筛选产生的空结果状态。
